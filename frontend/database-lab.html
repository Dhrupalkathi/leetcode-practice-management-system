DATABASE DESIGN

How the data is organized

Identity and access

users stores platform accounts and links to role. Learner and Organizer profile tables extend the common account record. PostgreSQL stores web sessions in user_sessions.

Problem catalogue

problem stores problem metadata. problem_topic resolves the many-to-many relationship between problems and topics. test_case separates public samples from hidden judging cases.

Execution lifecycle

submission records code attempts and execution state. submission_test_result stores per-test outcomes. A worker claims pending jobs and sends code to Judge0.

Competition and assessment

Contests use contest_registration and includes. Company assessments use assessment_problem, candidate and invites. A submission belongs to one actor and one context.

Governance and support

Review history, mentor feedback, support tickets, judge reviews, candidate activity indicators and audit events are stored separately so each workflow has its own record lifecycle.

Notifications

notification stores in-app messages for a user. Read state is tracked per notification and the API scopes reads and updates to the signed-in account.
